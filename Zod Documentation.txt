Zod Documentation
=================

Overview
--------
Zod is a TypeScript-first schema validation library. Schemas describe the expected shape and constraints of data; parsing checks input at runtime and returns validated data with inferred TypeScript types.

Typical uses include validating API payloads, environment configuration, user-submitted forms, and data loaded from external systems. Treat incoming or otherwise untrusted data as unknown until it has been checked.

Basic usage
-----------

```ts
import { z } from "zod";

const User = z.object({
  name: z.string(),
  age: z.number().int().nonnegative(),
});

type User = z.infer<typeof User>;

const result = User.safeParse(input);
if (result.success) {
  // result.data is validated and typed as User
  console.log(result.data.name);
} else {
  // result.error contains structured validation issues
  console.error(result.error.issues);
}
```

Common schema forms
-------------------
- Primitives: `z.string()`, `z.number()`, `z.boolean()`
- Arrays: `z.array(itemSchema)`
- Objects: `z.object({ field: fieldSchema })`
- Optional values: `schema.optional()`
- Nullable values: `schema.nullable()`
- Enumerated strings: `z.enum(["draft", "published"])`

Parsing
-------
Use `.parse(value)` when invalid input should throw a `ZodError`. Use `.safeParse(value)` when validation failure should be returned as a result object instead. Both methods return validated output, including any transformations defined by the schema.

Installation and project tasks
------------------------------
Install Zod in a Node.js project with:

```sh
npm install zod
```

The repository's `Makefile` exposes common tasks (`make install`, `make build`, `make test`, and `make lint`) that call the corresponding npm commands. Build, test, and lint targets require those scripts to exist in `package.json`.
